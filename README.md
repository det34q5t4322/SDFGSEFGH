# College Schedule & Telegram Mini App (ИСС9-25)

> **Для ИИ-агента и разработчиков:** Этот файл — актуальный контекстный брифинг проекта (обновлен в сентябре 2026 г.). Читай его в начале сессии, чтобы ориентироваться в архитектуре, модулях, API и базе данных без перечитывания всей кодовой базы с нуля.

---

## 1. Что это за проект

Многофункциональный студенческий сервис и **Telegram Mini App (TMA)** для Колледжа телекоммуникаций (МТУСИ), объединяющий:
1. **Интерактивное расписание занятий**: парсинг Google Таблиц колледжа (77 групп, 1–4 курсы, очное/заочное отделения). Основная целевая группа — `ИСС9-25`.
2. **Игровой хаб и Real-time 1v1 Дуэли**: многопользовательские дуэли по WebSockets (Тетрис, 2048, Подкидной Дурак, Змейка), система ELO-рейтинга с академическими рангами, соло-игры (Судоку, Chrome Dino, Сапёр).
3. **Дневник и оценки 1С:Колледж**: безопасная авторизация, просмотр успеваемости и среднего балла напрямую из облачной базы 1С.
4. **Проксирование аватарок Telegram**: локальное кэширование миниатюр профилей для обхода блокировок без VPN.
5. **Мультиплатформенность**: веб-версия (`https://schedule.dadrik.ru/`), Telegram-бот (`@Raddart_bot`), Telegram WebApp и нативный Android APK (`ru.dadrik.collegeschedule`).

## 2. Стек технологий и архитектура

- **Backend**: Python 3.12+, FastAPI (`server/app.py`), высокопроизводительный сервер **Granian** (Rust HTTP/1.1 & WebSocket), GZip-сжатие, HTTP middleware безопасности и rate limiting.
- **База данных**: **SQLite в WAL-режиме** (`server/data.db`, модуль `server/db.py`) с пулом таймингов, кэшированием в памяти и транзакционным батчингом активности (`flush_activity_batch`).
- **Real-Time WebSockets & Дуэли**: `server/duel_manager.py` — комнаты 1v1 (Best of 3), криптографические сиды (`secrets`), token-bucket rate limiting, grace-период на разрыв связи (15с), защита от читов и спама атак.
- **Проксирование аватарок**: `server/avatar_manager.py` — миниатюры 160×160, диск-кэш (TTL 24ч) со stale-while-revalidate, негативное кэширование (TTL 7д), защита от перебора ID (404 для неизвестных пользователей).
- **Интеграция с 1С**: `server/grades_1c.py` — GWT-протокол 1С, семафор конкурентности, шифрование сессий (Fernet), 15-минутный кэш-кулдаун.
- **Telegram Bot**: `python-telegram-bot` v20+ async (`server/bot.py`), глубокая интеграция WebApp, команды `/start`, `/app`, `/diary`, `/alarm`, `/support`.
- **Frontend**: Vanilla JS (ES6+) без тяжелых фреймворков, адаптивный CSS с 16 темами, тактильные неоновые кнопки, Lucide SVG иконки (zero-emoji), Service Worker (`sw.js`) с оффлайн-кэшем.
- **Инфраструктура**: VPS Ubuntu 24.04 (`194.87.92.31`), Nginx reverse proxy + HTTP/2, Let's Encrypt SSL (Certbot), Cloudflare DNS.

## 4. Реализованные системы и модули

### 4.1. Интерактивное расписание
- **Умное определение недели**: автоматический расчет чётности (I Числ. / II Знам.) по академическому календарю или имени вкладки.
- **Сдвиг на выходные**: в воскресенье автоматически отображается расписание на понедельник с информационным баннером.
- **Live-индикатор текущей пары**: точный обратный отсчет до конца пары или перемены (с индикацией большой перемены 30 мин).
- **Сигнал тревоги «Английский SOS»**: поиск ближайшей пары английского языка с виджетом и таймером обратного отсчета в боковом меню и в боте (`/alarm`).
- **3-уровневый конструктор интерфейса**: пользовательская настройка порядка блоков экрана, бокового меню и полей карточки пары с сохранением в `localStorage`.

### 4.2. Игровой хаб и Real-time 1v1 Дуэли
- **Сетевой протокол**: WebSocket `/ws/duel/{room_id}` со строгим форматом сообщений (`ready`, `state_update`, `attack`, `round_lost`, `rematch`).
- **Формат матча**: строго 1v1, Best of 3 (до 2 побед).
- **ELO Рейтинг (K=32)**: пересчет рейтинга после матча, защита от повторного начисления при дублировании сообщений.
- **Академическая система рангов**: 7 рангов («Адепт», «Специалист», «Магистр», «Архимаг» и др.) со звездами и модальным окном прогресса.
- **Античит и надежность**:
  - Атомарный перевод статуса в `countdown` до первого `await` (защита от race condition при одновременном `ready`).
  - Ограничение частоты атак (server-side attack throttling, BUG-EX1b).
  - Валидация score и штрафных линий (clamp 1–8).
  - Grace-период при обрыве связи (15 секунд с таймером в интерфейсе).
  - Фоновая очистка протухших комнат каждые 5 минут (`_cleanup_loop`).
  - Rate limit на подбор кодов комнат `/api/duel/join` (10 попыток/мин).

### 4.3. Проксирование аватарок Telegram
- Решает проблему блокировок `api.telegram.org` и `t.me` в РФ: клиент никогда не обращается к Telegram напрямую.
- Эндпоинт `GET /api/avatar/{telegram_id}` отдает локально закэшированные миниатюры 160×160 (~6–8 КБ).
- Защита от перебора ID (Anti-Enumeration): запрос неизвестного ID сразу возвращает `404 Not Found` без обращения к Bot API.
- Негативный кэш на 7 дней для пользователей без фото профиля.
- Заголовки `Cache-Control: public, max-age=86400, stale-while-revalidate=604800`.

### 4.4. Дневник 1С:Колледж
- Прямая работа с облачным GWT RPC интерфейсом `1c.ru`.
- Безопасное хранение зашифрованных сессий (AES/Fernet) в SQLite.
- Защита от перегрузки сервера 1С: семафор конкурентных запросов и 15-минутный кэш успеваемости.
- Просмотр оценок по предметам, типам работ (экзамен, зачет, контрольная) и расчет среднего балла.

### 4.5. Административная панель и безопасность
- Вход в админку строго для авторизованных администраторов по Telegram ID.
- Временные и перманентные баны пользователей с журналом аудита (`admin_audit_logs`).
- При бане интерфейс приложения ведет себя неотличимо от отсутствия связи (вечный скелетон), предотвращая реверс-инжиниринг.

## 5. Как запускать, тестировать и деплоить

### Локальная разработка:
```powershell
# Запуск FastAPI бэкенда
python -m uvicorn server.app:app --port 8089 --reload

# Запуск бота (отдельный терминал)
python server/bot.py
```

### Запуск QA тестов:
```powershell
# Регрессионный сьют дуэлей и race conditions
python scratch/qa_tests/test_bug006_regression.py

# Тесты безопасности аватарок и защиты от оракула
python scratch/qa_tests/test_avatar_security.py
```

### Деплой на продакшн (VPS `194.87.92.31`):
Все обновления доставляются через Git в ветку `main`:
```bash
# На VPS:
cd /var/www/college-schedule
git fetch origin main
git reset --hard origin/main
systemctl restart college-web college-bot
```

Логи сервисов:
```bash
journalctl -u college-web -f -n 50
journalctl -u college-bot -f -n 50
```
