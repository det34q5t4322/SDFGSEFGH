# College Schedule & Telegram Mini App (ИСС9-25)

> **Для ИИ-агента:** Этот файл — контекстный брифинг проекта. Читай его в начале сессии, чтобы ориентироваться в архитектуре, путях и ограничениях без перечитывания всей кодовой базы с нуля.

---

## 1. Что это за проект

Веб-сервис и Telegram Mini App (TMA) для отображения расписания занятий Колледжа телекоммуникаций (МТУСИ). Основная целевая группа — `ИСС9-25` (2 курс), всего в таблице обрабатывается 77 групп (1–4 курсы, очное и очно-заочное отделения). Сервис работает автономно в браузере (`https://schedule.dadrik.ru/`) и внутри Telegram через бота (`@Raddart_bot`).

---

## 2. Стек и архитектура

- **Backend**: Python 3.10+, FastAPI (`server/app.py`), Uvicorn, GZipMiddleware.
- **Telegram Bot**: `python-telegram-bot` v20+ async (`server/bot.py`). *(В ранних ТЗ упоминался aiogram, в коде фактически задействован python-telegram-bot)*.
- **Хранение данных (актуальное состояние)**: 
  - **Текущее**: Файловый JSON-кэш на сервере (`server/schedule_cache.json` ~10MB, `server/known_tabs.json`, `server/cached_groups.json`, `server/bot_users.json`).
  - **Запланированное**: Спроектирован переход на SQLite (`schedule.db`) для устранения блокировок дискового I/O при парсинге 10 МБ JSON.
- **Источник расписания**: Публичная Google Таблица колледжа (парсинг HTML-представления через `htmlview`/`pubhtml` в `server/parser.py`). Фоновый опрос каждые 30 секунд.
- **Frontend**: Vanilla JS (ES6+) без сборщиков, чистый CSS со стилями 16 тем, внешняя библиотека `sortable.min.js` (drag-and-drop).
- **Хостинг**: VPS Ubuntu 24.04 (`194.87.92.31`), Nginx reverse-proxy, SSL Let's Encrypt Certbot, домен `schedule.dadrik.ru`. Опциональный Cloudflare Worker (`cf-worker/worker.js`) для обхода блокировок Telegram API.

### Поток данных:
```
Google Sheets (HTML) ──[каждые 30с / parser.py]──> In-Memory Cache + schedule_cache.json
                                                           │
        ┌──────────────────────────────────────────────────┴───────────────────────┐
        ▼                                                                          ▼
FastAPI REST API (/api/schedule, /tabs)                             python-telegram-bot (/today, /week)
        │
        ▼
Vanilla JS SPA / Telegram Mini App (localStorage кэш + Service Worker offline v6)
```

## 3. Структура файлов и модулей

- `server/`
  - `app.py` (~680 строк) — точка входа FastAPI. Маршруты: `/api/schedule`, `/api/tabs`, `/api/teachers`, `/api/classrooms`, `/api/stats`, `/api/user-group`, `/api/english-alarm`, `/api/ping`. Статика смонтирована на `/static`. Фоновые задачи: `background_sync_task`.
  - `bot.py` (~820 строк) — логика Telegram-бота. Обработчики: `/start`, `/app`, `/today`, `/tomorrow`, `/week`, `/alarm`, `/group`, `/diary`, `/support`. Валидация WebApp HMAC: `verify_telegram_init_data()`.
  - `parser.py` (~1800 строк) — движок парсинга HTML Google Sheets, расписания звонков (`BELL_TIMES`, `BREAK_TIMES`), парсинг замен/отмен, статистика учебной нагрузки (`get_pairs_statistics`), тревога пар английского (`get_upcoming_alarm`).
  - `run_all.py` — локальный запуск бота и uvicorn в одном процессе.
  - `*.json` — файлы данных: `schedule_cache.json` (дамп расписания), `cached_groups.json` (список групп), `known_tabs.json` (метаданные вкладок недель), `teachers_fio.json` (справочник ФИО), `bot_users.json` (пользователи бота и их выбранные группы).
- `static/`
  - `app.js` (~5470 строк, монолит) — состояние `S`, API-клиент, рендеринг расписания, live-индикаторы текущей пары и перемен, 3-уровневый конструктор (`applyLayoutOrder`, `applyMenuConfig`, `applyCardConfig`), пресеты, localStorage sync.
  - `index.html` (~1080 строк) — SPA-разметка: верхний бар с кнопкой смены группы, баннер статуса выходного/следующей пары, полоса дней, контейнер пар, нижний таб-бар на 4 кнопки (`#bottomNavBar`), боковое меню-шторка (`#sidebarNav`), схематичный blueprint-редактор (`#screenBlueprintBuilder`), модалки тем, настроек и онбординга.
  - `style.css` (~5500 строк) — переменные дизайн-системы, 16 тем (`data-theme="..."`), стили для мобильного вьюпорта 360–420px, CSS-анимации.
  - `onboarding.js` (~350 строк) — пошаговый обучающий тур для первокурсников с сохранением статуса в localStorage.
  - `sw.js` — Service Worker (актуальный кэш `college-schedule-v6`, оффлайн fallback).
  - `sortable.min.js` — библиотека SortableJS для перетаскивания блоков и полей карточки.
  - `telegram-web-app.js` — официальный SDK Telegram WebApp.
- `cf-worker/worker.js` — Cloudflare Worker обратный прокси к `api.telegram.org`.
- `.env` / `.env.example` — переменные `BOT_TOKEN`, `WEB_APP_URL`, `PORT`, `TELEGRAM_API_URL`.
- `Система бана / прав / заметок / админки`: спецификация и протоколы в `promt_final_tg_notes_ban_admin.md` (доступ в админку строго по Telegram ID владельца через `initData`).

## 4. Ключевые концепции домена

1. **Числитель / Знаменатель**: Учебные недели чередуются. Чётность недели вычисляется в `server/parser.py` (`get_academic_week_info`) от 1 сентября учебного года либо парсится из названия вкладки Google Таблицы (`I Числ.` / `II Знам.`).
2. **Формат ячейки расписания**: Исходная ячейка таблицы содержит комбинированную строку (предмет, преподаватель, кабинет, подгруппа). Парсер разделяет её через регулярные выражения на поля: `subject`, `teacher`, `room`, `subgroup` (1/2 подгруппа), `type` (лек/пр/лаб), флаги `is_replacement` (замена) и `is_cancelled` (отмена).
3. **Определение активной недели и сдвиг выходных**: По текущей дате Москвы сопоставляется диапазон дат вкладки (например `07.09–12.09`). Если наступило **воскресенье**, система автоматически переключается на расписание понедельника следующей недели и показывает статусную плашку «Воскресенье — выходной. Показано расписание на завтра».

## 5. Реализованные крупные фичи

- **3-уровневый конструктор интерфейса** (экран, меню, шаблон карточки пары с 5 зонами): `static/app.js` (L4000–5350), `static/index.html` (`#screenBlueprintBuilder`, `#layoutEditorBar`).
- **Схематичный (Blueprint) режим редактора**: миниатюрные плашки для перетаскивания без тяжелого рендеринга реальных пар: `static/app.js`, `static/style.css`.
- **PWA и отказоустойчивый оффлайн-режим**: `static/sw.js` (`college-schedule-v6`), `static/app.js` (`showOfflineBanner`, кэш в localStorage).
- **Интерактивный онбординг для первокурсников**: `static/onboarding.js`, вызов из бокового меню.
- **Live-индикатор текущей пары и переменных**: расчет точного времени до звонка, индикация большой перемены (30 мин): `static/app.js` (`updateLiveStatus`), `server/parser.py`.
- **Нижний таб-бар на 4 пункта без дублирования с меню**: `Расписание`, `Преподаватели`, `Аудитории`, `Ещё`: `static/index.html`, `static/style.css`, `static/app.js`.
- **Очищенное боковое меню («Ещё»)**: 3 секции: *Часто используемое* (обновление, темы), *Справочное и сервисы* (1С, статистика, обучение, поддержка), *Системное* (сброс интерфейса): `static/index.html`.
- **Статичный бейдж текущей группы**: `static/index.html` (`#sidebarGroupBadge`), предотвращающий дублирование смены группы.
- **Интеграция с Дневником 1С**: прямая ссылка с иконкой внешнего перехода и fallback-обработкой для Telegram WebApp: `static/app.js` (`openDiaryExternal`).
- **Telegram HMAC-валидация и защита от IDOR**: `server/bot.py` (`verify_telegram_init_data`), `server/app.py` (`set_api_user_group`).
- **Telegram-гейт, бан-система, админ-панель и заметки**: архитектурная спецификация в `promt_final_tg_notes_ban_admin.md`.

## 6. Важные решения и почему именно так

- **SQLite вместо PostgreSQL**: VPS имеет 1 ГБ оперативной памяти. SQLite не требует отдельного демона, исключает расход RAM на сетевой пул соединений и ускоряет выборку данных прямо в процессе Python.
- **Сайт ориентирован на Telegram WebApp**: исключает необходимость в громоздких формах регистрации и ввода паролей; аутентификация пользователя происходит мгновенно по криптографической HMAC-подписи `initData`.
- **Одинаковое поведение бана и входа без Telegram (вечный скелетон/загрузка)**: защита от целенаправленного реверс-инжиниринга. Сторонний сканер или заблокированный пользователь не получают статусных кодов (403/401) и явных признаков блокировки.
- **Отсутствие дублирования путей навигации**: «Оформление и темы» доступно строго через боковое меню; переключение разделов — строго через нижний таб-бар; смена группы — строго через шапку `[ 👥 ИСС9-25 ▾ ]`.

---

## 7. Известные ограничения / сознательно отложено

- **Мульти-колледж**: парсер и структура ячеек жестко адаптированы под регламент таблиц МТУСИ. Поддержка других учебных заведений спроектирована концептуально, но не реализована в коде.
- **Парсинг оценок из 1С**: автоматический сбор баллов отложен из-за закрытого протокола авторизации 1С и юридических рисков пользовательского соглашения. Реализован защищенный прямой переход.
- **Завершение миграции на SQLite**: текущая кодовая база стабильно работает на файловом JSON-кэше; код перехода на SQLite выделен в отдельный изолированный этап.

## 8. Как тестировать и деплоить

### Локальный запуск:
```powershell
python -m uvicorn server.app:app --port 8089 --reload
# Открыть в браузере: http://127.0.0.1:8089/?group=ИСС9-25
```

### Тестирование мобильного вида:
Все интерфейсные изменения **обязательно** тестируются при ширине вьюпорта **360–420px** (типовые экраны смартфонов) с включенной эмуляцией тач-событий.

### Процедура деплоя на продакшн (VPS `194.87.92.31`):
1. **Создать бэкап** перед обновлением (архив сохраняется в `/var/backups/college-schedule/`):
   ```bash
   tar -czf /var/backups/college-schedule/prod-backup-$(date +%Y%m%d_%H%M%S).tar.gz -C /var/www college-schedule
   ```
2. **Обновить код из Git**:
   ```bash
   cd /var/www/college-schedule && git fetch origin main && git reset --hard origin/main
   ```
3. **Перезапустить службы**:
   ```bash
   systemctl restart college-web college-bot
   ```
4. **Просмотр логов**:
   ```bash
   journalctl -u college-web -f -n 50
   journalctl -u college-bot -f -n 50
   ```
5. **Чеклист после деплоя (3-5 минут)**:
   - Проверить HTTP 200 на `https://schedule.dadrik.ru/?group=ИСС9-25`.
   - Проверить актуальность кэш-бастера ассетов в HTML (`?v=...`).
   - Открыть бота `@Raddart_bot` и запустить WebApp через кнопку.
   - Убедиться в отсутствии критических ошибок в `journalctl -u college-web`.

## 9. Формат работы с изменениями

1. **Реальные баги** исправляются сразу с точечной верификацией без предварительного раздувания планов.
2. **Архитектурные изменения и новые фичи** — сначала формулируются в плане/отчёте, согласуются с пользователем и только после одобрения реализуются.
3. **Пошаговая реализация**: каждая крупная задача разбивается на независимые шаги, тестируемые по отдельности.
4. **Неизменность внешнего поведения**: рефакторинг бэкенда или стилей не должен ломать существующие API (`/api/schedule`, `/api/tabs`, `/api/english-alarm`) и пользовательские привычки работы с интерфейсом.
